타이포그래피

Display·Body 전체 타입 스케일. 폰트 패밀리는 Pretendard(사용자 환경에 미설치 시 시스템 폰트로 대체).

Display

랜딩·로그인 헤더 등 큰 타이틀에 사용. Display는 전부 tokens/_breakpoint.scss가 만드는 반응형 --bds-type-display-*를 씁니다 — 고정값이 아니라 브라우저 창 폭을 줄이면 실제로 작아집니다.

Body

2Xs ~ 2Xl. 대부분의 컴포넌트 텍스트가 이 스케일을 사용합니다. 이 중 Lg·Xl·2Xl만 반응형 --bds-type-body-*를 쓰고(창 폭에 따라 변함), 2Xs·Xs·Sm·Md는 반응형 변형이 없어 고정값입니다.

Weight

사용법

스케일을 적용하는 방법은 두 가지입니다. 화면 마크업에서는 클래스를 쓰고, 디자인시스템 컴포넌트를 만들 때는 text() 믹스인을 씁니다. 둘 다 abstracts/_maps.scss의 같은 맵을 읽으므로 값이 갈릴 일이 없습니다.

1. 클래스 — 화면 마크업에서
<h2 class="bds-text-display-xs bds-fw-bold">제목</h2>
<p class="bds-text-body-md">본문</p>
<span class="bds-text-body-sm bds-fw-medium">보조 텍스트</span>

.bds-text-*가 사이즈와 행간을 담당하고(Display는 폰트 패밀리까지), .bds-fw-*가 굵기를 담당합니다. 굵기 클래스는 생략할 수 있으며, 생략하면 부모에서 상속받은 굵기를 그대로 씁니다.

2. 믹스인 — 컴포넌트 SCSS에서
@use '../abstracts/mixins' as mix;      // 파일 맨 위에 한 번

.my-card__title {
  @include mix.text(display-xs, bold);  // 사이즈, 굵기
}

.my-card__body {
  @include mix.text(body-md);           // 굵기 생략
}

굵기를 생략하면 font-weight 선언 자체가 나가지 않습니다. 상속값을 유지해야 하는 자리에서 이 형태를 씁니다. 없는 키를 쓰면 컴파일이 실패하면서 쓸 수 있는 키 목록을 출력하므로, 오타가 조용히 넘어가지 않습니다.

어느 쪽을 쓰나

프로젝트 화면 마크업은 클래스, 디자인시스템 컴포넌트는 믹스인입니다. 컴포넌트가 마크업에 클래스를 요구하면 쓰는 쪽이 매번 두 클래스를 정확히 붙여야 하고, 하나라도 빠지면 컴포넌트가 깨집니다.

쓸 수 있는 키

클래스로 쓸 때는 앞에 bds-text- · bds-fw-를 붙이고, 믹스인에는 키 이름을 그대로 넣습니다.
